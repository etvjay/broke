# Verified Receipts Implementation Plan

> Superseded on 22 Nov 2026 by the Why It Broke design, which is pending approval. This plan will not be built. See [Why It Broke design](../specs/2026-11-22-why-it-broke-design.md). Kept for the record.

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a small poll app that a coding agent writes while Kane CLI checks each UI change in a real browser. Each check run is saved as a chained receipt, the README shows the red-to-green history, and a verifier proves the receipts were not edited.

**Architecture:** Node 24 ES modules with no npm dependencies. `app/` is the poll app. `scripts/` holds the verify runner, the verifier, the approval tool, and the Stop-hook wrapper. Kane CLI runs three plain-English flows in a real browser against the app. Each verify run writes one JSON receipt, chained to the previous receipt by hash, and commits it. A Stop hook runs verify when an agent turn ends after a change to `app/`.

**Tech Stack:** Node 24 (`node:http`, `node:test`, `node:crypto`, `node:child_process`), git 2.43, GitHub CLI 2.98, Kane CLI 0.10.4. cloudflared only if Task 1 fails.

**Spec:** `docs/superpowers/specs/2026-11-22-verified-receipts-design.md`

## Global Constraints

- No npm dependencies. No third-party APIs, logins, or databases.
- The app listens on `PORT` (default 3000). `npm start` keeps data in `./data`, which is gitignored. Verify starts the app on a free port with a fresh temp data directory.
- Kane call: `kane-cli run <objective> --target desktop --url <url> --headless --agent --timeout 240 --max-steps 30`. Pass the objective as one argument, with no shell.
- Receipt hash: SHA-256 over canonical JSON (keys sorted) of the receipt without its `hash` field. Genesis `previousHash` is 64 zeros. Each receipt records `trigger`: `manual` or `stop-hook`.
- Verify exit codes: 0 pass, 1 fail, 2 error or refusal. Stop-hook exit codes: 0 allows the stop, 2 blocks it.
- Attempt cap: 5 per app tree. Credit floor: 2,000, below which verify refuses to run.
- Kane runs with the build from the first page change. The flows are approved before any page code exists, and the Stop hook is enabled in the same commit as the first page slice.
- Fixed UI labels, used by the flows: `Question`, `Option 1` to `Option 4`, `Create poll`, `Vote for <option>`, `<n> votes` (`1 vote` when n is 1), `You already voted on this poll.`
- The user's Git identity is used as is. The agent never sets it and never uses `--no-verify`.
- Never commit secrets, Kane config, or `data/`.
- Committed evidence is redacted before commit (Task 4). No email address, local home path, IP address, or auth value goes into the public repo.

## Review Focus

1. An empty or over-long question, or fewer than 2 or more than 6 options, gets a 400 with a readable message and stores nothing. Test: Task 6.
2. A double click or resubmitted vote from one browser counts once. The second request gets 409. Tests: Task 6 (server) and Task 7 slice C (buttons disabled while a request runs).
3. A corrupt or unreadable data file does not crash the app. The bad file is kept as `polls.json.bad-<time>`, and the app starts empty. Test: Task 6.
4. A tampered, deleted, or reordered receipt makes `receipts:verify` fail and name the receipt. Test: Task 8.
5. A Kane run that ends with no verdict (crash, timeout, login or credit error) is recorded as `error`, never as a pass. Test: Task 4.
6. Committed evidence has no email address, local home path, IP address, or auth value. Test: Task 4 (fixture pack) and Task 10 (search of the real repo).

### Task 4: Verify runner with a fake Kane (TDD)

**Files:** `scripts/verify.mjs`, `scripts/lib/git.mjs`, `scripts/lib/kane.mjs`, `scripts/lib/receipts.mjs`, `scripts/lib/evidence.mjs`, `test/kane.test.mjs`, `test/verify.test.mjs`, `test/evidence.test.mjs`, `test/fixtures/fake-kane`, `test/fixtures/stub-app/server.mjs`, `package.json` (adds `verify`).

**Interfaces:**
- Produces: `parseKaneStream(stdoutText) -> { runEnd, pack, steps, failingStep }`. It skips lines that are not JSON, because Kane can print notices outside the JSON stream.
- Produces: `verdictFrom({ exitCode, runEnd }) -> 'pass' | 'fail' | 'error'`. Status `passed` maps to pass, `failed` maps to fail, and anything else, including no `run_end`, maps to error.
- Produces: `buildReceipt({ index, previousHash, commit, appTree, kaneVersion, trigger, result, flows, createdAt }) -> receipt`, with `hash` filled in. Each flow entry carries `creditsConsumed` from `run_end` and its evidence files with their SHA-256.
- Produces: `writeFixBrief(receipt) -> markdown`, saved as `receipts/NNNN-brief.md`.
- CLI: `node scripts/verify.mjs [--root <dir>]`. The `KANE_BIN` environment variable overrides the Kane binary (default `kane-cli`). The `APP_CMD` variable overrides the app start command (default `node app/server.mjs`, with `PORT` and `DATA_DIR` set). The `VERIFY_TRIGGER` environment variable sets `trigger` (default `manual`).

**Behavior, in order:**
1. Take the lock `.factory/state/verify.lock` (exclusive create). If it exists, exit 2 with `verify already running`. Read credits with `${KANE_BIN} balance` (line `Available credits: N`). Below 2,000, exit 2 with a message and write no receipt.
2. Refuse a dirty tree (`git status --porcelain`, ignoring `.factory/state/`). Exit 2 with no receipt, and tell the user to commit.
3. Check each flow's hash against `flows/approvals.json`. If any flow is unapproved, write an error receipt and run no Kane checks.
4. Start the app on a free port with a fresh temp `DATA_DIR`. Wait up to 15 seconds for `/api/health`. If it never answers, write an error receipt.
5. Run each flow with Kane. Parse the NDJSON. Read the pack path from the `coverage` event's `pack` field, which the smoke run set even though coverage was `skipped`. Unzip it with the system `unzip` command (the README lists it as a requirement for `npm run verify`), redact it, and copy the files to `receipts/evidence/NNNN-<flow>/`. No `run_end`, a crash, a timeout, a missing pack, or a redaction leftover is an error verdict (Review Focus 5 and 6).
6. Stop the app. Build and write the receipt. Write the fix brief when the result is not pass. Update `RECEIPTS.md` with the chain head and a table row. Then commit only those paths (`git commit -- receipts RECEIPTS.md`) with the message `receipt NNNN: <result>`.
7. Exit 0 for pass, 1 for fail, 2 for error. Release the lock on every exit path.

**Evidence redaction:** every file except screenshots (`.jpg`, `.png`) is scanned as text. Email addresses and IPv4 addresses become `<redacted>`. Local home paths become `/home/user`, the local user name becomes `user`, and the Kane profile name becomes `profile`. Token, secret, password, or key assignments with a value become `<redacted>`. In the HAR, cookie and authorization header values are removed. Screenshots are copied unchanged. The same scan runs again after redaction, and any match left over fails the flow (step 5).

- [ ] Write failing tests for `verdictFrom` (passed, failed, and no `run_end` with exit 124 as error, Review Focus 5), canonical hash stability, and `previousHash` linking. Parse `test/fixtures/smoke-run.ndjson`. Write failing redaction tests: a fixture pack with an email, a home path, a user name, and an IP is cleaned and passes the re-scan (Review Focus 6). A scan that still finds a match fails the flow closed.

Cover pass (`FAKE_KANE_MODE=pass`), fail (`fail`, which must write a brief), no verdict (`none`), and a dirty tree (refused, no receipt).
- [ ] Implement the runner and the fake Kane. The fake prints the same NDJSON event shapes as the real CLI. Make the tests pass.
- [ ] Commit `feat: verify runner and receipts`.

### Task 5: Stop hook and agent rules (TDD), not enabled yet

**Interfaces:** Consumes the exit codes and receipt layout from Task 4.

**Files:** `scripts/stop-hook.mjs`, `test/stop-hook.test.mjs`, `AGENTS.md`.

**Stop-hook behavior:**
1. Read the hook's stdin JSON. Ignore it if it does not parse. Find the repo root with `git rev-parse --show-toplevel`. Read the attempt count for the current app tree, which is `git rev-parse HEAD:app`. If it is 5 or more, exit 0 with `Attempt cap reached. Failures are in receipts/.`
2. If `app/` has uncommitted changes, exit 2 with `Commit your app changes so Kane can verify them, then stop again.` Count an attempt.
3. If no receipt exists, run verify. Otherwise compare `git rev-parse HEAD:app` with the newest receipt's `appTree`. If they match and the newest result is pass, exit 0. If they match and the newest result is fail or error, exit 2 with the brief path, without running Kane.
4. Every exit 2 above adds one attempt to `.factory/state/attempts.json` as `{ appTree, count }`. A new app tree resets the count. The cap in step 1 ends any loop, so the hook does not need `stop_hook_active`.
5. Otherwise run `VERIFY_TRIGGER=stop-hook node scripts/verify.mjs`. On pass, exit 0. On fail or error, count an attempt, print the brief path and the failing step to stderr, and exit 2.

**AGENTS.md rules:** commit each app change before the turn ends. During verify-driven fixes, edit only `app/`. Never edit `flows/`, `receipts/`, `RECEIPTS.md`, `scripts/`, `.factory/`, or `data/` to get a pass. Never run `npm run flows:approve`. Stop and report when a flow looks wrong. Stop after 5 attempts. Never rewrite or delete a receipt.

- [ ] Write failing tests using the fake Kane for four cases: an uncommitted app change blocks (exit 2), an unchanged tree after a pass allows the stop (exit 0), an unchanged tree after a fail blocks without a new run, and the fifth attempt allows the stop with the cap message.
- [ ] Implement the hook and make the tests pass.
- [ ] Write `AGENTS.md` with the rules above. Commit `feat: stop hook and agent rules`.

### Task 8: Receipt verifier (TDD)

**Interfaces:** Consumes `sha256Hex` and `canonicalJson` (Task 3) and the receipt layout (Task 4).

**Files:** `scripts/receipts-verify.mjs`, `scripts/lib/verify-chain.mjs`, `test/receipts-verify.test.mjs`.

**Checks, in order:**
1. Receipt files are `0001.json`, `0002.json`, with no gaps. The index inside each file matches its file name.
2. Each stored `hash` matches the recomputed hash. Each `previousHash` matches the previous receipt's `hash`, and the first one is 64 zeros.
3. Git history: every committed version of each receipt file matches HEAD's version, and no commit deletes a receipt (`git log --diff-filter=D -- receipts/`).
4. Each flow hash in a receipt matches that flow file at `receipt.commit`. An approval record with the same hash must exist in `flows/approvals.json` at `receipt.commit`.
5. Each evidence file listed in a receipt exists, and its SHA-256 matches the receipt.
6. `RECEIPTS.md` shows the last receipt's hash as the chain head.
7. The app at HEAD is verified: the newest receipt whose `appTree` equals `git rev-parse HEAD:app` exists and has result pass. Otherwise output `FAIL app at HEAD is not verified` and exit 1, so an unverified change cannot hide behind older receipts.

Output: `OK <n> receipts, chain head <first 12 hex>`, or `FAIL receipt NNNN: <reason>` with exit code 1.

- [ ] Write failing tests in a temp repo built from verify output (fake Kane). Cover: a failed receipt edited to read as pass, a deleted receipt, two receipts swapped, and a flow changed without approval. Each must fail and name the receipt. Add a case where an app commit has no receipt, and one where the newest receipt for HEAD's app is a fail; both must fail. Add a passing case.
- [ ] Implement the verifier and make the tests pass. Then run `npm run receipts:verify` on the real repo.
- [ ] Commit `feat: receipt verifier`.

This check cannot detect a rewritten history. The README states that limit, and the published chain head is the external check. It also cannot prove that the runner is unchanged. `AGENTS.md` forbids agent edits to `scripts/` and `.factory/`, and git history shows any change.
